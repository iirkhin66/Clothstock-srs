# Спецификация требований к программному обеспечению

**Система учёта товаров магазина одежды «ClothStock»**  
Версия 1.0 | Соответствует IEEE 830 / ISO 29148

---

## 1. Введение

### 1.1 Цель документа

Настоящий документ является SRS системы «ClothStock» — веб-приложения для учёта товаров небольшого магазина одежды.

**Проблема:** менеджеры ведут учёт остатков вручную в Excel или бумажных тетрадях, что приводит к ошибкам, пересортице и потере продаж из-за незамеченного дефицита.

- **Воздействует на:** владельцев магазинов, менеджеров по товарам, кассиров.
- **Результатом является:** финансовые потери от неверных остатков, затраты времени на ручные инвентаризации.
- **Выигрыш от ПО:** автоматический учёт в реальном времени, управление состоянием товара, отчёты о прибыли и убытках.

### 1.2 Область применения

Система предназначена для небольших магазинов одежды (сегмент XS — до 10 сотрудников, S — 10–25 сотрудников). Не является кассовым ПО и не автоматизирует бухгалтерский учёт.

### 1.3 Определения и сокращения

| Термин | Определение |

## 2. Общее описание

### 2.1 Описание продукта (шаблон Мура)

- **Для** — владельцев и менеджеров небольших магазинов одежды;
- **которые** — испытывают проблему ошибочного учёта остатков и трудозатратной инвентаризации;
- **этот** продукт — ClothStock;
- **является** — веб-приложением для учёта товаров;
- **который** — позволяет управлять товарами, отслеживать состояние каждой единицы и рассчитывать прибыль/убытки за любой период;
- **в отличие от** — ведения учёта вручную в Excel или бумажных тетрадях;
- **наш продукт** — обеспечивает мгновенный доступ к актуальным данным с любого устройства без специальных знаний.

### 2.2 Контекстная диаграмма

```
                    [ Менеджер ]
          добавление/состояние/параметры ↕ подтверждение

[ PostgreSQL ] ←→ [     ClothStock      ] ←→ [ Модуль экспорта ]
  данные/запросы   система учёта товаров      запрос/PDF+Excel

       поиск/просмотр ↕ результат    управление доступом ↕ настройки
          [ Кассир ]                      [ Администратор ]

                         событие дефицита ↕ статус
                            [ Email / SMS ]
```

| Субъект | Тип | Входящие данные | Исходящие данные |
|---------|-----|-----------------|------------------|
| Менеджер | Пользователь (Р) | Подтверждение операций | Управление товарами, состоянием, отчёты |
| Кассир | Пользователь (U) | Результаты поиска, состояние | Поисковые запросы |
| Администратор | Пользователь (XS) | Настройки системы | Управление учётными записями и правами |
| PostgreSQL | БД | Данные | SQL-запросы |
| Email/SMS | Внешний сервис | Статус отправки | События дефицита |
| Модуль экспорта | Внешний сервис | Файлы PDF/Excel | Запросы на отчёты |

### 2.3 Анализ конкурентов

Сегмент: XS–S (малый розничный магазин одежды). Конкуренты: **Shopify POS**, **ЕКАМ**, **МойСклад**.

| Проблема | Сегмент | Shopify POS | ЕКАМ | МойСклад | Приоритет |
|----------|---------|-------------|------|----------|-----------|
| Учёт остатков товаров | XS, S | + | + | + | e |
| Добавление и редактирование товаров | XS, S | + | + | + | e |
| Поиск по артикулу и категории | XS, S | + | + | + | e |
| Управление состоянием товара (склад/зал/продан) | XS | — | — | — | e |
| Уведомление о низком остатке | XS | + | + | + | u |
| Отчёт о прибыли/убытках за период | XS, S | + | — | + | u |
| Офлайн-режим | XS | — | + | + | d |
| Штрихкодирование | XS | + | + | — | d |

**Вывод:** управление состоянием товара отсутствует у всех конкурентов — это ключевая ниша. Отчёт о прибыли/убытках есть у Shopify POS и МойСклад, но не у ЕКАМ.

### 2.4 Целевая аудитория — роли пользователей

#### Кассир (U — обычный пользователь)
Работает в торговом зале. Потребности: найти товар, проверить его состояние и остаток. Не редактирует данные.

#### Менеджер (Р — продвинутый пользователь)
Ответственен за каталог. Потребности: добавлять/удалять товары, изменять параметры, управлять состоянием (склад/зал/продан), формировать отчёты о прибыли и убытках.

#### Администратор (XS — корпоративный, до 10 сотрудников)
Создаёт учётные записи, назначает роли, настраивает права доступа к конкретным функциям.

### 2.5 Ограничения

- Система не является кассовым ПО и не выдаёт фискальные чеки.
- Интеграция с бухгалтерским ПО (1С) не предусмотрена в версии 1.0.
- Мобильное приложение в версии 1.0 не разрабатывается — только веб-интерфейс.
- Для работы требуется интернет-соединение.

## 3. Функциональные требования

### 3.1 Варианты использования

#### UC-01: Управление товарами

| Поле | Содержание |
|------|------------|
| **Актор** | Менеджер |
| **Предусловие** | Пользователь авторизован с ролью «Менеджер» |
| **Основной поток** | 1. Нажать «Добавить товар». 2. Заполнить форму: название, артикул, категория, размер, цена. 3. Нажать «Сохранить» — система добавляет позицию со статусом «На складе». 4. Для удаления: выбрать товар → «Удалить» → подтвердить. |
| **Альт. потоки** | 2а. Артикул занят — ошибка «Артикул занят». 3а. Незаполненное поле — форма подсвечивает его. 4а. Ненулевой остаток — система запрашивает дополнительное подтверждение. |
| **Постусловие** | Товарная позиция добавлена или удалена; история изменений сохранена. |

#### UC-02: Изменение параметров товара

| Поле | Содержание |
|------|------------|
| **Актор** | Менеджер |
| **Предусловие** | Пользователь авторизован с ролью «Менеджер»; карточка товара открыта |
| **Основной поток** | 1. Открыть карточку товара. 2. Нажать «Редактировать». 3. Изменить нужные поля (название, категория, размер, цена). 4. Нажать «Сохранить». |
| **Альт. потоки** | 3а. Некорректное значение (отрицательная цена) — ошибка валидации. 4а. «Отмена» — изменения не сохраняются. |
| **Постусловие** | Параметры обновлены; в истории зафиксированы дата, пользователь и изменённые поля. |

#### UC-03: Управление состоянием товара

| Поле | Содержание |
|------|------------|
| **Актор** | Менеджер |
| **Предусловие** | Пользователь авторизован с ролью «Менеджер»; карточка товара открыта |
| **Основной поток** | 1. Открыть карточку товара. 2. Нажать «Изменить состояние». 3. Выбрать: «На складе» / «В торговом зале» / «Продан». 4. Нажать «Применить». 5. При переводе в «Продан» — остаток уменьшается на единицу. |
| **Альт. потоки** | 3а. Состояние совпадает с текущим — предупреждение. 5а. Остаток = 0 — система запрещает перевод в «Продан». |
| **Постусловие** | Состояние обновлено; остаток пересчитан; изменение зафиксировано в истории. |

#### UC-04: Управление учётными записями сотрудников

| Поле | Содержание |
|------|------------|
| **Актор** | Администратор |
| **Предусловие** | Пользователь авторизован с ролью «Администратор» |
| **Основной поток** | 1. Открыть раздел «Пользователи». 2. Нажать «Добавить сотрудника». 3. Заполнить: имя, email, роль. 4. Настроить права: доступ к управлению товарами и/или к изменению состояния. 5. Нажать «Создать» — система отправляет письмо-приглашение. |
| **Альт. потоки** | 3а. Email уже зарегистрирован — ошибка. 5а. Почтовый сервис недоступен — запись сохранена, выводится предупреждение. |
| **Постусловие** | Учётная запись создана с заданными правами; сотрудник получает приглашение по email. |

#### UC-05: Расчёт прибыли и убытков

| Поле | Содержание |
|------|------------|
| **Актор** | Менеджер / Администратор |
| **Предусловие** | Пользователь авторизован; в системе есть данные о товарах за выбранный период |
| **Основной поток** | 1. Открыть раздел «Отчёты». 2. Выбрать интервал (дата начала — дата конца). 3. Нажать «Сформировать отчёт». 4. Система рассчитывает разницу между стоимостью имеющихся и проданных товаров за период. 5. Отображается итог: прибыль (+) или убыток (−). 6. Скачать в PDF или Excel. |
| **Альт. потоки** | 2а. За период нет данных — «Нет данных за указанный период». 4а. Ошибка расчёта — логирование + предложение повторить. |
| **Постусловие** | Отчёт сформирован и доступен для скачивания. |

## 4. Нефункциональные требования

| ID | Приоритет | Характеристика | Описание |
|----|-----------|----------------|----------|
| NFR-01 | e (Must) | Производительность | Система возвращает результат поиска за < 3 секунды при каталоге до 5 000 позиций |

## 6. Критерии приёмки

| ID | Критерий | Способ проверки | Приоритет |
|----|----------|-----------------|-----------|
| AC-01 | Менеджер может добавить товар — он появляется в каталоге со статусом «На складе» | Тест добавления | e (Must) |
| AC-02 | Поиск по артикулу возвращает результат за < 3 секунды | Нагрузочный тест | e (Must) |
| AC-03 | Менеджер может перевести товар в «Продан» — остаток уменьшается на 1 | Тест состояния | e (Must) |
| AC-04 | Кассир не может изменять параметры или состояние товара | Тест прав доступа | e (Must) |
| AC-05 | Отчёт о прибыли/убытках за период формируется и скачивается за < 10 секунд | Тест отчёта | u (Should) |
| AC-06 | При остатке ниже порога менеджер получает уведомление | Тест уведомления | u (Should) |
