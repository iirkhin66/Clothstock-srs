# Спецификация требований к программному обеспечению

**Система учёта товаров магазина одежды «ClothStock»**  
Версия 1.0 | Соответствует IEEE 830 / ISO 29148

---

## 1. Введение

### 1.1 Цель документа

Настоящий документ является Спецификацией требований к программному обеспечению (SRS) системы «ClothStock» — веб-приложения для учёта товаров небольшого магазина одежды.

**Проблема:** менеджеры небольших магазинов одежды ведут учёт остатков вручную — в таблицах Excel или бумажных тетрадях. Это приводит к ошибкам в данных, пересортице и потере продаж из-за незамеченного дефицита.

- **Воздействует на:** владельцев магазинов, менеджеров по товарам, кассиров.
- **Результатом является:** финансовые потери от неверных остатков, затраты времени на ручные инвентаризации.
- **Выигрыш от ПО:** автоматический учёт остатков в реальном времени, мгновенный поиск, уведомления о дефиците.

### 1.2 Область применения

Система «ClothStock» предназначена для небольших магазинов одежды (сегмент XS — до 10 сотрудников, S — 10–25 сотрудников). Система не является кассовым ПО и не автоматизирует бухгалтерский учёт.

### 1.3 Определения и сокращения

| Термин | Определение |
|--------|-------------|
| SRS | Спецификация требований к программному обеспечению |
| Товарная позиция | Единица номенклатуры с уникальным артикулом, названием, категорией, размером, ценой и остатком |
| Артикул | Уникальный буквенно-цифровой код товара |
| Остаток | Текущее количество товара на складе или в торговом зале |
| Порог уведомления | Минимально допустимый остаток, при достижении которого система формирует предупреждение |
| FR | Функциональное требование (Functional Requirement) |
| NFR | Нефункциональное требование (Non-Functional Requirement) |
| e / u / d | Приоритеты MoSCoW: essential (обязательно), useful (полезно), desirable (желательно) |
| UC | Вариант использования (Use Case) |

## 2. Общее описание

### 2.1 Описание продукта (шаблон Мура)

- **Для** — владельцев и менеджеров небольших магазинов одежды;
- **которые** — испытывают проблему ошибочного учёта остатков и трудозатратной инвентаризации;
- **этот** продукт — ClothStock;
- **является** — веб-приложением для учёта товаров;
- **который** — позволяет в реальном времени управлять остатками, искать товары и получать уведомления о дефиците;
- **в отличие от** — ведения учёта вручную в Excel или бумажных тетрадях;
- **наш продукт** — обеспечивает мгновенный доступ к актуальным остаткам с любого устройства без специальных знаний.

### 2.2 Контекстная диаграмма

```
             [ Менеджер ]
           добавление/остатки ↕ подтверждение

[ PostgreSQL ] ←→ [ ClothStock ] ←→ [ Модуль экспорта ]
  запросы/данные    система учёта    запрос/файлы PDF+Excel

           поиск/остаток ↕ результат     управление ↕ настройки
          [ Кассир ]              [ Администратор ]

                    событие дефицита ↕ статус
                       [ Email / SMS ]
```

**Внешние субъекты:**

| Субъект | Тип | Входящие данные | Исходящие данные |
|---------|-----|-----------------|------------------|
| Менеджер | Пользователь (Р) | Подтверждение операций | Добавление/редактирование товаров, корректировка остатков |
| Кассир | Пользователь (U) | Результаты поиска, остатки | Поисковые запросы |
| Администратор | Пользователь (XS) | Настройки системы | Управление учётными записями |
| PostgreSQL | БД | Данные из БД | SQL-запросы |
| Email/SMS | Внешний сервис | Статус отправки | События дефицита товара |
| Модуль экспорта | Внешний сервис | Файлы PDF/Excel | Запросы на формирование отчётов |

### 2.3 Анализ конкурентов

Анализ проведён для сегмента XS–S (малый розничный магазин одежды).  
Конкуренты: **Shopify POS**, **ЕКАМ**, **МойСклад**.

| Проблема | Сегмент | Shopify POS | ЕКАМ | МойСклад | Приоритет |
|----------|---------|-------------|------|----------|-----------|
| Учёт остатков товаров | XS, S | + | + | + | e |
| Добавление и редактирование товаров | XS, S | + | + | + | e |
| Поиск по артикулу и категории | XS, S | + | + | + | e |
| Уведомление о низком остатке | XS | + | + | + | u |
| Отчёт по остаткам категорий | XS, S | + | — | + | u |
| Офлайн-режим | XS | — | + | + | d |
| Штрихкодирование | XS | + | + | — | d |

**Вывод:** все конкуренты закрывают базовый учёт остатков. Ключевые возможности для ClothStock: отчёт по категориям (отсутствует у ЕКАМ), уведомления о дефиците, добавление товара за ≤ 4 действия.

### 2.4 Целевая аудитория — роли пользователей

#### Кассир (U — обычный пользователь)
Работает с товарами в торговом зале. Потребности: быстро найти товар, проверить остаток. Не редактирует данные и не управляет пользователями.

#### Менеджер по товарам (Р — продвинутый пользователь)
Ответственен за актуальность каталога. Потребности: добавлять/редактировать/удалять позиции, корректировать остатки, задавать пороги уведомлений, формировать отчёты.

#### Администратор (XS — корпоративный, до 10 сотрудников)
Владелец магазина или IT-ответственный. Потребности: создавать учётные записи, назначать роли, блокировать доступ.

### 2.5 Ограничения

- Система не является кассовым ПО и не выдаёт фискальные чеки.
- Интеграция с бухгалтерским ПО (1С) не предусмотрена в версии 1.0.
- Мобильное приложение в версии 1.0 не разрабатывается — только веб-интерфейс.
- Для работы требуется интернет-соединение.

## 3. Функциональные требования

### 3.1 Варианты использования

#### UC-01: Добавить товарную позицию

| Поле | Содержание |
|------|------------|
| **Актор** | Менеджер |
| **Предусловие** | Пользователь авторизован с ролью «Менеджер» |
| **Основной поток** | 1. Нажать «Добавить товар». 2. Заполнить форму: название, артикул, категория, размер, цена, количество. 3. Нажать «Сохранить». 4. Система проверяет данные и добавляет позицию в каталог. |
| **Альт. потоки** | 2а. Артикул уже существует — система выводит ошибку «Артикул занят». 3а. Обязательное поле не заполнено — форма подсвечивает незаполненное поле. |
| **Постусловие** | Новая товарная позиция отображается в каталоге с указанным остатком. |

#### UC-02: Найти товар

| Поле | Содержание |
|------|------------|
| **Актор** | Кассир / Менеджер |
| **Предусловие** | Пользователь авторизован; в каталоге есть хотя бы одна позиция |
| **Основной поток** | 1. Ввести запрос в строку поиска (название, артикул или категория). 2. Нажать Enter или «Найти». 3. Система отображает список совпадений. 4. Пользователь выбирает позицию и видит её карточку. |
| **Альт. потоки** | 3а. Совпадений нет — система выводит «Товар не найден». |
| **Постусловие** | Пользователь видит актуальную карточку товара с остатком и ценой. |

#### UC-03: Скорректировать остаток

| Поле | Содержание |
|------|------------|
| **Актор** | Менеджер |
| **Предусловие** | Пользователь авторизован с ролью «Менеджер»; карточка товара открыта |
| **Основной поток** | 1. Открыть карточку товара. 2. Нажать «Изменить остаток». 3. Ввести новое количество и указать причину (поступление / списание / инвентаризация). 4. Нажать «Применить». Система сохраняет запись в историю. |
| **Альт. потоки** | 3а. Введено нецелое или отрицательное значение — система выводит ошибку валидации. |
| **Постусловие** | Остаток обновлён; запись в истории изменений сохранена с датой и именем пользователя. |

#### UC-04: Управлять учётными записями сотрудников

| Поле | Содержание |
|------|------------|
| **Актор** | Администратор |
| **Предусловие** | Пользователь авторизован с ролью «Администратор» |
| **Основной поток** | 1. Открыть раздел «Пользователи». 2. Нажать «Добавить сотрудника». 3. Заполнить: имя, email, роль. 4. Нажать «Создать». Система отправляет письмо-приглашение. |
| **Альт. потоки** | 3а. Email уже зарегистрирован — система выводит ошибку. 4а. Почтовый сервис недоступен — учётная запись сохраняется, выводится предупреждение. |
| **Постусловие** | Учётная запись создана; сотрудник может войти по ссылке из письма. |

### 3.2 Матрица классификации требований

| Категория | Кассир | Менеджер | Администратор |

| **Управление остатками** | FR-05: Кассир может просмотреть текущий остаток товара | FR-06: Менеджер может скорректировать остаток товара; FR-07: Менеджер может установить порог уведомления | — |

```
│  (уникальных    │░░░░░│ FR-06, FR-07, FR-08,      │
│  требований нет)│░░░░░│ FR-09                     │
└────────┬────────┘░░░░░└──────────────┬────────────┘
         │  ОБЩИЕ:                     │
         │  FR-01 поиск товара         │     ┌──────────────────┐
         │  FR-05 просмотр остатка     │     │  Администратор   │
         └─────────────────────────────┘     │  FR-10, FR-11,   │
                                             │  FR-12           │
                                             └──────────────────┘
```

## 4. Нефункциональные требования

| ID | Приоритет | Характеристика | Описание |
|----|-----------|----------------|----------|
| NFR-01 | e (Must) | Производительность | Система возвращает результат поиска за < 3 секунды при каталоге до 5 000 позиций |
| NFR-02 | e (Must) | Надёжность | Система доступна не менее 99% рабочего времени (9:00–21:00) |
| NFR-03 | e (Must) | Безопасность | Система хранит пароли в хешированном виде (bcrypt); все соединения по HTTPS |
| NFR-04 | u (Should) | Удобство | Пользователь может добавить товар не более чем за 4 последовательных действия |
| NFR-05 | u (Should) | Совместимость | Система работает в браузерах Chrome, Firefox, Edge (последние 2 версии) |
| NFR-06 | d (Could) | Масштабируемость | Система поддерживает каталог до 50 000 товарных позиций без деградации производительности |

## 6. Критерии приёмки

Продукт считается готовым при выполнении всех критериев **e (Must)** и не менее 80% критериев **u (Should)**.

| ID | Критерий | Способ проверки | Приоритет |
|----|----------|-----------------|-----------|
| AC-01 | Менеджер может добавить товар и он немедленно появляется в списке | Тест добавления товара | e (Must) |
| AC-02 | Поиск по артикулу возвращает нужную позицию за < 3 секунды | Нагрузочный тест поиска | e (Must) |
| AC-03 | Кассир не может редактировать или удалять товары | Тест разграничения прав | e (Must) |
| AC-04 | При остатке ниже порога менеджер получает уведомление | Тест уведомления | u (Should) |
| AC-05 | Отчёт об остатках формируется и скачивается за < 10 секунд | Тест генерации отчёта | u (Should) |
